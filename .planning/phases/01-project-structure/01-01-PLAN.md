<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local filesystem -> git remote | Files committed from working tree cross into the public git remote (GitHub). Anything ignored here stays local; anything tracked is published. |
| Claude -> external URLs | When SETUP-03 is satisfied, Claude can issue outbound HTTP requests via WebFetch to any URL. Outbound network access introduces a new egress vector. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | .gitignore exclusion rules (SETUP-01) | mitigate | Add `output/` and `*.pdf` lines. Acceptance criteria verify both patterns are present via exact regex match. Acceptance criteria also re-verify the pre-existing `profile.yaml` exclusion was not removed during the edit, which prevents the most likely failure mode (accidental deletion of the rule that keeps PII out of git). |
| T-01-02 | Information Disclosure | output/ directory tracked via .gitkeep (SETUP-02) | mitigate | The `.gitkeep` file is empty by design (zero bytes). Acceptance criteria require the file exist AND that adding a dummy `.pdf` to output/ is still ignored — this proves the directory placeholder does not accidentally start tracking generated PDFs. |
| T-01-03 | Elevation of Privilege | .claude/settings.json WebFetch grant (SETUP-03) | accept | The phase success criterion explicitly requires a permission that "allows Claude to fetch URLs" without scoping. Domain-scoping (e.g. `WebFetch(domain:linkedin.com)`) is rejected as a mitigation because it would not satisfy SETUP-03 as written. Risk profile: WebFetch is read-only HTTP GET, cannot write to external services, and the human-in-the-loop submission rule in CLAUDE.md (never submit a form without explicit user confirmation) limits how URL content can be acted upon. Accepted for milestone v1.0 Foundation; revisit if/when a future requirement adds outbound write surface (e.g., webhooks). |
| T-01-04 | Tampering | .claude/settings.local.json (existing file) | mitigate | Task 2 acceptance criteria require settings.local.json's permissions.allow array still contain all 17 pre-existing entries after the edit. This prevents accidental clobbering of the user's local Chrome DevTools / git / gh permissions, which would silently break their interactive workflow. |
</threat_model>
